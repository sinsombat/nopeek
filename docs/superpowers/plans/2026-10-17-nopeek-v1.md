# NoPeek v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** สร้าง menu-bar app "NoPeek" (macOS 26+, SwiftPM, ไม่มี dependency) ที่ตรวจจับการแคปจอ / remote control / กล้อง / ไมค์ แจ้งเตือนทันที เก็บ evidence log และให้ความสำคัญสูงสุดกับ actor ระดับองค์กร

**Architecture:** SwiftPM 2 target — `PWCore` (library: parser, classifier, pipeline, pollers, log, config — ทุกอย่างเทสต์ได้) + `NoPeekApp` (executable: menu bar, notifications, banner, wizard). App ประกอบเป็น `.app` ด้วยสคริปต์ + ad-hoc codesign + LaunchAgent

**Tech Stack:** Swift 6.x (Xcode CLT), SwiftPM, AppKit, UserNotifications, AVFoundation, CoreAudio, sysctl; ไม่มี third-party dependency

**Spec:** `docs/superpowers/specs/2026-10-17-nopeek-design.md` (executor ต้องอ่าน spec คู่กับ plan นี้)

## Global Constraints

- Platform: macOS 26+ (ทดสอบบน 27.0.1); ต้องการแค่ Xcode CLT; **ห้ามเพิ่ม dependency ภายนอก**
- **ห้ามขอ TCC permission ใดๆ ยกเว้น notification** (ห้าม Screen Recording / Accessibility / Full Disk)
- Bundle id: `com.sinsombat.nopeek`; app เป็น `LSUIElement=true` (ไม่มีใน Dock)
- Paths (ห้ามเปลี่ยน): config `~/.config/nopeek/config.json` · log `~/Library/Logs/NoPeek/events-YYYY-MM-DD.ndjson` · state `~/Library/Application Support/NoPeek/` · banner text/labels ตาม spec §6
- Tier names (literal): `ORG`, `REMOTE`, `NORMAL`, `SYSTEM_NOISE`, `ALLOWLIST`
- ลำดับ classifier (literal order): org → systemNoise → allowlist → remote → normal
- ค่าคงที่: throttle 60s · banner cooldown 60s · gap threshold default 15 นาที · retention 30 วัน · detect ≤5s · idle CPU <1% / memory <100MB
- ภาษา: TH default + EN; ทุก string UI ผ่าน `Strings` table (ห้าม hardcode)
- ad-hoc codesign (`codesign --force --deep -s -`); README สองภาษา (EN+TH)
- Kill/Auto-kill: manual ต้องยืนยันทุกครั้ง + pid-reuse guard (ชื่อ process ต้องตรงก่อนยิง); auto-kill default ปิด, เฉพาะ user processes, loop guard `autoKillMaxPerHour`; ห้าม auto-kill root (v1); ทุก kill บันทึก event `process-kill` (SYSTEM_NOISE/lifecycle)

## Review Focus

จุดที่ spec ระบุเจตนาไว้แต่เทสต์ปกติอาจไม่ครอบ — ทุกข้อมีเทสต์ใน task ที่ระบุ:

1. **Log line ที่ field ถูก redact (`<private>`) หรือสตริง log ต่างจากที่คาด** → ต้องไม่ crash และยังแจ้งเตือนด้วย "ไม่ทราบผู้แคป" ได้ (Task 4)
2. **บรรทัด ndjson ขาด/ถูกตัดกลางคัน** (อ่านไฟล์ขณะเขียน) → parser ข้ามบรรทัดนั้น ไม่ล้มทั้ง stream (Task 4, 5)
3. **`config.json` เสีย (JSON พัง / ผิด type / ค่าว่าง)** → ใช้ defaults ทั้งชุด, กฎ ORG ยังทำงาน, ไม่ crash; แจ้งเตือน reload error ทาง log (Task 10)
4. **นาฬิกาเครื่องกระโดด / sleep-wake** → gap detector ต้องไม่รายงานค่าติดลบ/ไร้สาระ และ gap หลัง sleep ต้องยังถูกต้องเชิงตรรกะ (Task 9)
5. **เหตุการณ์ burst (Mission Control กดรัวๆ)** → pipeline.throttler รวมเป็น count ไม่เด้งถี่, log โตแบบมีขอบเขต, UI ไม่ค้าง (Task 7, 11)
6. **Kill/Auto-kill พลาดเป้า** → pid-reuse (ยิงผิด process) และ respawn-loop (ฆ่าไม่จบ) → guard ต้องจับ: pid+ชื่อต้องตรงก่อนยิง, ฆ่าเกินโควตา/ชม. ต้องหยุด + แจ้ง (Task 21)
